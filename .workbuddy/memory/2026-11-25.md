# 2026-11-25

## V3.9.33 —— 英寸板 + Gerber 写法的钻孔文件：孔径缩成 1/25.4，钻孔整批消失

用户反馈：`Temp/bug测试/KGDY-03A(gerber).zip` 预览正常，导入画布后**直插焊盘和过孔的钻孔全部丢失**。

### 根因（两层，都在孔径单位上）

样本 `kgdy-03a.txt` 不是 Excellon，而是 **Gerber 写法**：`%FSLAX25Y25` + `%MOIN` +
`%ADD10C,0.015748` + `D03` 闪绘，没有 `M48` 头。解析器判钻孔靠 `M48` / `T0` 特征
（`04-gerber-parser.js:54`），所以 `data.isDrill = false`，走普通 Gerber 通道：
坐标乘了 25.4（正确），**光圈参数没乘**。而 `05-pad-tool.js` 的钻孔分支按注释
「已在解析阶段换算」直接 `mmOf()`，0.4mm 被读成 0.0157mm（≈0.6mil），等于 0 尺寸孔。

第二层：`isViaFlash` 的铜环是 `(flashDia - drillDia)/2`，英寸的光圈减 mm 的孔径 →
铜环恒为负 → `_isThruHolePad` 永远 false → **插件焊盘整批改判成过孔**。
所以只修孔径不够，两处都得改。

预览之所以正常，是因为渲染层自己按 `(!isDrill && units==='in') ? 25.4 : 1` 乘了 `unitScale`
（`09-ui.js:329`）—— 判断口径和 PadTool 不一致。

### 改动

- `05-pad-tool.js` 顶部新增 `drillApertureMM(data, raw)`：`isDrill → 原值`，否则按
  `units==='in' ? ×25.4 : ×1`。判据与 `09-ui.js` 的 `unitScale` 完全一致。
- 应用三处：预扫描的 `_dia`（决定过孔/插件盘判据）、钻孔分支圆孔 `w/h`、槽孔 `dia`。
- `isViaFlash` 增加 `_scale` 入参，调用处传 `toMM(1)`，让铜环与孔径同单位比较。
- `09-ui.js:750` 槽孔绘制补 `* unitScale`（同一类问题，英寸 Gerber 槽孔以前被画细 25.4 倍）。

### 实测（148 孔 = 65×0.4mm 过孔 + 83 插件孔）

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| PAD / 带孔 | 76 / 2 | 142 / 68 |
| layer 12 通孔盘 | 2 | 68 |
| VIA | 146（孔径错乱） | 80（65 过孔 + 15 裸露孔） |
| 焊盘孔径 | 1.47 / 1.55 mil | 27.6~59.1 mil = 0.7~1.5mm |
| 过孔孔径 | 0.6~7 mil | 15.75 mil = 0.4mm |
| LINE / POLY | 12613 / 1188 | 12613 / 1188（不变） |

剩 15 个 ≥1.05mm 的孔（4.5mm 安装孔、1.3mm 裸孔等）在 .gtl/.gbl 里**确实没有焊盘**
（逐坐标搜过，无 D03 也无图形），按原规则保留为独立过孔，不是本次问题。
