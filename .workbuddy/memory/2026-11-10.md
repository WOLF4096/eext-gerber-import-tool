## V3.9.25：两个用户上报的解析 bug

样本：`Temp/bug测试/Gerber过孔异常.zip`（Altium 24，18 层）、`Gerber焊盘异常.zip`（EAGLE 9.7）。

### 1) 钻孔 METRIC,LZ 的尾零没补回 → 整片过孔缩到原点

- 现象：`X0019Y00005` 应读作 (19.000, 0.500) mm，插件读成 (0.019, 0.005)。
- 根因：无小数点坐标一律 `parseFloat(v)/10^dec`，等价「右对齐补前导零」。
  **钻孔的 LZ/TZ 语义和 Gerber 的 %FS 相反**：
  Gerber `%FSLA`＝省略前导零（右对齐，补前）；`%FST`＝省略尾零（左对齐，补后）；
  Excellon `METRIC,LZ`＝**保留**前导零＝省略尾零（补后）；`TZ`＝补前。
- 改动：
  - `06-utils.js`：`detectGerberDeclarations` 新增 `gZero/dZero`（'start'|'end'）；
    `%FS` 正则改为 `%FS([LTAI]*)X(\d)(\d)Y(\d)(\d)`；钻孔认 `(LZ|TZ)`。新增 `gerberCoordValue()`。
  - `04-gerber-parser.js`：`state.format.zeroPad`；`handleStd` **只在 `zeroPad==='end'` 才走补位**，
    `'start'` 保持 `val/div`（补前导零不改数值，热路径零开销）；`handleExt` 的 %FS 兜底同步 int/zeroPad。
  - `05-pad-tool.js`：G85 槽孔的 `manualToMM` 改用同一套换算。

### 2) P（正多边形）光圈被当矩形 → 八角焊盘变 1.65×8mm 长条

- `%ADD17P,1.64956X8X22.5`：参数是「外径 X **边数** X 旋转角」，`extractRawData` 的兜底分支把
  `p[1]` 当高度，于是「8 边」成了 8mm。
- 修法：新增 `type === 'P'` 分支，按外径/边数/起始角生成顶点 → `shape:'POLYGON'` + 去重索引。
  全链路（padMatchBoxMM / netPadOutline / 专业版 / 标准版导出）本来就支持 POLYGON。
- 顺带：`isEq` 对 POLYGON 一律 false → 同形上下层被误判成「内外层不同」，白搭 `["RECT",10,10]`
  specialPad。改成逐顶点比对（0.005mm）。

## V3.9.26：来源软件识别从「只认嘉立创」扩到各家注释

需求：只要注释里出现软件名，尽量识别出来（给了 Altium 与 EAGLE 两个原始片段）。

- `06-utils.js` `detectEasyEdaSource()` → `detectGerberSource()`（`09-ui.js` 调用点同步改名），
  四层策略：
  1. 标准 X2/X3 `TF.GenerationSoftware,<厂商>,<软件>,<版本>`；**Excellon 写 `;GenerationSoftware,...` 没有
     `TF.` 前缀**，正则要 `(?:TF\.)?`；
  2. 嘉立创私有 `G04 EasyEDA Pro v2.2.32.3, ...`；
  3. `Created by …` / `; DRILL file {…}`；
  4. 兜底：注释行里出现已知软件名（`SOURCE_KNOWN_NAMES` 表）。
- **多文件取最优**：结果带 `hasVer`，优先采用带版本号的那条。EAGLE 的铜层只写
  `G04 EAGLE Gerber RS-274X export`（无版本），版本在钻孔头 `;GenerationSoftware,Autodesk,EAGLE,9.7.0`。
- **坑：`; Drill file` 不能跨行匹配**。老式钻孔头两行 `; Drill file` + `; Format: 2.4 (00.0000)`，
  正则里 `\s*` 会吃换行拼成假软件名 `; Format: 2.4`。改成 `DRILL file\s*\{([^}\r\n]{1,80})\}`（必须带花括号）。
- 版本清洗：去 `v`（仅后跟数字，否则 PADS 的 `VX.2.4` 会变 `X.2.4`）、去括号备注、去逗号/空格后说明、
  逐段保留纯数字（`2.1.40.832e02bb` → `2.1.40`）；**别用 `\d+(?:\.\d+)*` 取第一段**，
  它会把 `2.1.40.832` 当成版本（832 后跟 e02bb 就断了，逐段 split 才对）。
- 时间：`TF.CreationDate` / `;CreationDate` / EasyEDA / KiCad `date` 都能取，带 `Z`/`+08:00`
  的走 `new Date()` 转本地（EAGLE 的 UTC 时间不再显示成字面值）。
- UI：`#prop-soft` 加 `max-width:210px` + ellipsis + `title`，长名字不挤压标签。
- 显示格式统一「名称 版本」，**不再带 v**（`嘉立创EDA专业版 2.1.40`）。
- 验证：构造用例 23 项全过；真实样本 9 个目录结果正确（g0802/g5 文件里确实没写软件名 → null）；
  解析/焊盘回归照旧（77/79 一致）。
- 版本 3.9.25 → 3.9.26，`npm run build` 通过，`build/dist/eext-gerber-import_v3.9.26.eext`（49 项）。

## V3.9.27：Altium 槽孔（M15/M16）+ 渲染补齐

样本：`Temp/bug测试/LT.zip`（单面板 180 槽）、`AD.zip`（4 层板 88 槽）。
完整分析在 `Temp/bug测试/异常报告_LT_AD.md`。

三层缺陷：

1. **入口过滤整份丢弃**：`looksLikeGerberContent` 的 7 条规则对 `*SlotHoles.TXT` 全不命中
   （坐标行是 `G00X…`，行首不是 X）。而且 `M0?[248]\b` 匹配不了 `M48`、`G0?[0-4]\b`
   匹配不了 `G00X`、`T\d+\s*C` 匹配不了 `T1F00S00C0.6500` —— 全是 `\b` / 空白的坑。
   改成 `M48\b` 单列、`G0?[0-4](?![0-9])`、`T\d+\w*C[\d.]+`、`[XY][-+]?\d`。
2. **解析器只认 G85**：Excellon 的 rout 模式是 `G00 → M15 → G01 → M16`，
   `M` 不在坐标正则里被忽略 → 一条槽拆成两颗圆孔。新增 `state.routStart` + `isRapid`，
   逐段出 `type:6`；**M15 时要 pop 掉 G00 的同点圆孔**，否则槽的一端多一颗孔。
   顺带修 G85 的两种写法：`X1Y1G85X2Y2`（Altium）vs `X2Y2G85`（标准 X2），
   用「G85 之后还有没有坐标」区分起点，原来只对前者正确。
3. **槽孔匹配不到焊盘**：0.05mm 距离容差。LT 槽中心与焊盘重合能过；AD 偏 0.1mm（偏心槽），
   88 条只匹配 40 条，其余 48 条变成「直径=槽长」的独立过孔。
   新增 `padBoxOf` / `findPadContaining`：按「槽中心落在焊盘包围盒内」兜底。

渲染：
- 槽孔：`drawCanvas` 本来就有 `type:6` 分支（lineCap round 的粗线），过去没数据可画；现在有了。
- **P 光圈（正多边形）画布是空白** —— Flash 分支里没有 `P`。新增后按外径/边数/起始角画。
  边数与角度必须用 `rawParams`（`p[]` 已乘单位，英寸文件会变成 203 边）。
- 「通孔」统计改为 `type:3 + type:6`（LT 75→255，AD 1512→1600）。

其它：`industry-common.js` 补 `.GPT`/`.GPB` 锡膏层规则（之前落文档层 13）。

数据：LT 255 孔（180 槽全落焊盘 SLOT）；AD 1600 孔（88 槽全落位，修复前 40）。
