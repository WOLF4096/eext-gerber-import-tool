## V3.9.25：两个用户上报的解析 bug

样本：`Temp/bug测试/Gerber过孔异常.zip`（Altium 24，18 层）、`Gerber焊盘异常.zip`（EAGLE 9.7）。

### 1) 钻孔 METRIC,LZ 的尾零没补回 → 整片过孔缩到原点

- 现象：`X0019Y00005` 应读作 (19.000, 0.500) mm，插件读成 (0.019, 0.005)。
- 根因：无小数点坐标一律 `parseFloat(v)/10^dec`，等价「右对齐补前导零」。
  **钻孔的 LZ/TZ 语义和 Gerber 的 %FS 相反**：
  Gerber `%FSLA`＝省略前导零（右对齐，补前）；`%FST`＝省略尾零（左对齐，补后）；
  Excellon `METRIC,LZ`＝**保留**前导零＝省略尾零（补后）；`TZ`＝补前。
- 改动：
  - `06-utils.js`：`detectGerberDeclarations` 新增 `gZero/dZero`（'start'|'end'）；
    `%FS` 正则改为 `%FS([LTAI]*)X(\d)(\d)Y(\d)(\d)`；钻孔认 `(LZ|TZ)`。新增 `gerberCoordValue()`。
  - `04-gerber-parser.js`：`state.format.zeroPad`；`handleStd` **只在 `zeroPad==='end'` 才走补位**，
    `'start'` 保持 `val/div`（补前导零不改数值，热路径零开销）；`handleExt` 的 %FS 兜底同步 int/zeroPad。
  - `05-pad-tool.js`：G85 槽孔的 `manualToMM` 改用同一套换算。

### 2) P（正多边形）光圈被当矩形 → 八角焊盘变 1.65×8mm 长条

- `%ADD17P,1.64956X8X22.5`：参数是「外径 X **边数** X 旋转角」，`extractRawData` 的兜底分支把
  `p[1]` 当高度，于是「8 边」成了 8mm。
- 修法：新增 `type === 'P'` 分支，按外径/边数/起始角生成顶点 → `shape:'POLYGON'` + 去重索引。
  全链路（padMatchBoxMM / netPadOutline / 专业版 / 标准版导出）本来就支持 POLYGON。
- 顺带：`isEq` 对 POLYGON 一律 false → 同形上下层被误判成「内外层不同」，白搭 `["RECT",10,10]`
  specialPad。改成逐顶点比对（0.005mm）。

### 验证方法与数据（可复用）

- 脚本都在 `Temp/`：`test_parse.js`（单测）、`test_full.js`/`test_via.js`（全流程）、
  `regress_compare.js`（新旧逐文件坐标对比）、`regress_pad.js`/`regress_via.js`（新旧图元对比）。
- 新旧对比的做法：`git show HEAD:iframe/js/xx.js > Temp/regress_old/js/xx.js`，再用 vm 把
  04+05+06 装进两个独立 context。**注意 generatePrimitives 的 ticket/id 是共享计数器，
  焊盘数量一变全部行都不同 —— 比对前要剥掉 `"ticket":N` / `"id":"eN"`**。
- 结果：79 个样本 77 个坐标完全一致；pad_issue 焊盘 193→193、图元行 2461→2461、非焊盘逐条一致；
  via_issue 钻孔范围 0.00~47.98 → 0.50~49.50（板框 0~50），导线/折线/覆铜逐条一致。
- 性能：2.1MB 丝印层解析 461ms（旧版 483ms）。**别把补位做成无条件调用**，2MB 层会多 150ms。
