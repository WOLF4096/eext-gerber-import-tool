### 2) 实现「导出标准版」（嘉立创EDA标准版 PCB 源码 .json）

格式出自 lceda 官方文档 + 参考文件实测：

- **1 标准版单位 = 10 mil = 0.254 mm**；`X = 4020 + mmX/0.254`，`Y = 3560.5 - mmY/0.254`（X 右正、Y 上正）。
- 图元字段数（必须逐位对齐）：PAD 20 / VIA 8 / HOLE 6 / TRACK 7 / ARC 8 / CIRCLE 10 / COPPERAREA 19 / SOLIDREGION 10。
- 图层映射与内部编号**顺序不同**：内部 5/6(阻焊)↔标准 7/8，内部 7/8(锡膏)↔标准 5/6，
  内部 9/10(装配)↔标准 13/14，11(板框)→10(BoardOutLine)，12→11(Multi)，13→12(Document)，
  14→15，内层 15..46 → 21..52。
- ARC 的 `d` 串：`M sx,sy A r,r 0 <largeArc> <sweep> ex,ey`；**G03(逆时针) → sweep=0，G02 → 1**（实测得出）。
  半圆判 largeArc 要用 `> 180.0001` 容差，否则浮点 180.00000000000003 会误判成优弧。
- 覆铜 → COPPERAREA；板框层折线 → layer 10 的闭合 TRACK；其它层折线 → 带线宽的 TRACK；
  非铜区域 → SOLIDREGION。
- 代码位置：`iframe/js/08-export.js` 的 `STD_*` 常量 + `stdNum/stdX/stdY/stdU/stdFlattenPath/stdPathStr/
  stdPointStr/stdCopperArea/buildStandardSource/exportForStandard`。
- 校验通过：顶层键 / layers(53) / objects(17) / canvas / DRCRULE 与参考完全一致；
  8 个共有图元（3 SMD PAD、1 通孔 PAD、3 VIA、1 HOLE、1 CIRCLE）位置尺寸字段与参考**逐字段相同**；
  BBox 得 `{x:4020,y:3166.8,w:393.7,h:393.7}`，与参考一致。

### 3) 标准版 Gerber 渲染 / 导入修复（均先复现、后验证）

| 缺陷 | 证据 | 修复 |
|---|---|---|
| **整圆丢失**：标准版把 `CIRCLE` 图元导出成「起点=终点」的 360° 圆弧，`ctx.arc(sa==ea)` 画出空路径 | 画布该处 0 像素，参考光栅化是一整个圆（recall 0.836） | `09-ui.js` type1 圆弧 + 区域路径弧：识别整圆后 `moveTo(圆周点)` 再画 0~2π。recall → 0.876 |
| **整圆导入错误**：导出成 angle=360 的两点圆弧，EDA 无法还原 | V2 输出 `["ARC",…,2630,2835,2630,2835,360,…]` | `05-pad-tool.js extractRawData`：拆成两段对向 180° 半圆（几何等价） |
| **阻焊/助焊扩展丢失**：`%AM` 宏做出来的掩膜焊盘 `w=h=0`，`calcExp` 直接 return null | 参考源码该焊盘 `solderExpansion=0.2`(=0.0508mm)，工具算出 `null` | `consolidate` 新增 `effWH()`：POLYGON 焊盘用 path 包围盒代替 w/h。修复后三个焊盘均得 0.0508mm = 参考值 |
| **覆铜图元类型错误**：无私有段标记来源的覆铜被降级成 0.1mm 细线「闭合折线」，导入后整块铜只剩发丝线 | 参考源码对应图元是 COPPERAREA / SOLIDREGION | `effMode === 'POUR'` 改为 `rawFills.push()`（实心填充），与画布渲染一致 |
