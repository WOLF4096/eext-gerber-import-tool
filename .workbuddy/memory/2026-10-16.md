### 2) 槽孔被拉长到 1000mm+（Gerber_PCB1_2023-11-07.zip）

**根因**：PAD 的第 14 个字段 `slotPointArr`（槽中心线两端点）一直是空串，
只写了 `holeLength`。标准版拿不到中心线时会把槽从坐标原点拉到焊盘中心，
于是槽长变成「原点到焊盘」的距离（该板 ≈1300mm）。

**修复**（`buildStandardSource` 的槽孔分支）：
- `PadTool` 里槽孔 `w = 全长（中心距+钻刀直径）`、`h = 槽宽`；
- `holeR = stdU(槽宽/2)`、`holeLength = stdU(全长)`；
- `slotPointArr = 中心 ± (全长-槽宽)/2 · (cos(drill.rotation), sin(drill.rotation))`，
  即沿**钻刀方向**（G85 行方向）取中心线端点。
- 官方参考实测关系：`holeLength = 中心线长 + 2*holeR` ✓ 自洽。

验证：4 个槽孔焊盘全部给出 slotPointArr，`holeR=2, holeLength=8.5/12`，
中心线长 4.5/8.0 + 2×2 = 8.5/12 ✔；画布上槽孔本来就画得对（`cmd.type===6` 用钻刀直径画圆头线），
1000mm 只出现在标准版源码里。

### 3) 飞针文件 → 焊盘编号

`buildStandardSource` 新增：读 `flyingProbeData.pins`（fields 里找 PIN_NAME/PIN_X/PIN_Y）建
netlistPoints，写进 PAD 的第 9 个字段（编号），匹配不到回退 `'1'`。
**关键坑**：飞针的 PIN_X/PIN_Y 不一定在焊盘几何中心 —— 异形（多边形）焊盘可偏 27mil
（实测 SW 开关焊盘：polygon bbox 中心 691.5mil，引脚 664.51mil）。所以两级匹配：
① 中心 2.5mil 内含；② 引脚落在焊盘包围盒内（取离中心最近者，需给多边形焊盘传 bbox）。

验证：`Gerber_PCB1_2024-11-18.zip` 63 个焊盘 100% 命中（39 中心 + 24 包围盒），编号分布
1×24 / 2×20 / 3..20 各 1，与引脚预期一致；此前全部是 `1`。

## 追加：焊盘去重 bug + 飞针标注层（同日第三轮）

### 1) 矩形多层焊盘 → 顶层焊盘 + 过孔（`Gerber_PCB1_2023-11-07.zip` 复现 3 个）

**根因**（不是合并逻辑的问题，而是**焊盘被提前丢掉了**）：
`05-pad-tool.js` 的 PAD flash 分支里有个「同位置已有 POLYGON 焊盘就跳过」的去重，
`rawPads` 是**所有图层的公共数组**，而 `loadedFiles` 的处理顺序是
顶铜(1) → 顶丝印(3) → **顶阻焊(5)** → 顶锡膏(7) → **底铜(2)** → …。
顶阻焊的宏多边形焊盘先入队，于是同坐标的底铜矩形焊盘（以及内层 15/16）被整批跳过。
→ 节点只有 top、没有 bottom → `tryMergeDrillToPad` 判为「单面焊盘」不合并
→ 导出成「顶层焊盘 + 独立过孔」，底层没焊盘。

**修复**：去重加 `existing.layerId === layerId`（同层内仍然去重）。

验证（PCB1 2023-11-07）：3 个目标位置 `top=RECT bottom=RECT drill=Y inners=2`；
独立过孔 231→228（正好少 3 个）；导出成
`PAD~RECT~4218.6496~3686.5748~6~6~11~~1~1.7992~<4 角点>~0~gge1106~0~~Y~0~~0.2008~…`
（与用户给的官方样例同字段布局）。
**5 个历史样本回归结果与修复前完全一致**（1.4/5/0802-2/上.pcbdoc/12层PCB），无副作用。

## 追加：RS-274X 导入专业版 EDA 的四类错误（同日第六轮，版本 → 3.6.0）

用户真机反馈：**渲染对、导入错**；嘉立创内部格式没问题。全部定位到「无段标记来源」那条分支。

### 1) 异形焊盘丢「组合 + 焊盘编号」（有飞针文件时）

`generatePrimitives` 的引脚匹配只按「焊盘中心 ±2.5mil」，而飞针的引脚锚点在异形焊盘上常偏
（开关类实测偏 27mil）→ 编号退化成 `"1"`、`groupId` 归零。**改为共用 `buildFlyingPinIndex` /
`flyingPinAt` / `padMatchBoxMM` 的两级匹配**（与标准版导出、画布标注同一套），并跳过 `PAD***` 占位。
实测 63 焊盘全部拿到组合（异形 24/24），编号分布与标准版导出一致。

### 2) 过孔铜环/尺寸/阻焊开窗丢失（三块样本全中）

`consolidate` 里钻孔 ↔「过孔铜盘/阻焊盘」用 `toFixed(3)` **精确键**，而同一物理点在 Gerber 与
钻孔文件之间实测差 0.003~0.015mm → 大面积匹配失败 → `padDia` 退化成钻孔直径、阻焊扩展算不出。
**改为 0.05mm 容差栅格就近归并**（`viaNodeAt` / `findViaNode`）。
实测「padDia 退化成钻孔径」的个数：1.4_Gerber 99→9、0802-2 105→3、5_Gerber 24→16。

### 3) 插件焊盘被当成过孔

`isViaFlash` 只有「圆形 + ≥2 铜层 + 附近有钻孔」。**新增判据：钻孔 ≥0.6mm 且铜环 ≥0.25mm → 插件焊盘**
（两条件同时满足才改判，常量 `THT_DRILL_MIN` / `THT_RING_MIN`；`_nearestDrill` 顺带记录钻孔孔径）。

### 4) 覆铜变成一整块实心矩形

**修复**：提取阶段把清区（区域 / 闪绘 / 线段）统一收集为 ring，按包含关系（含"最大重叠"兜底）

## 2026-10-17 00:20 新增「生成网络」（物理连通性 → 分配 NET***）

用户要求：参照 `Temp/生成网络/GenerateNet.html` 的逻辑实现生成网络；把

### 参考实现的算法（已移植）
铜层图元（焊盘 / 过孔 / 导线 / 圆弧 / 折线 / 填充）→ 空间网格求候选对 → 几何连通判定 →
并查集求连通分量 → 每个分量定一个网络名 → 回填。命名优先级：已有真实名 > 通用 `NET\d+`；
都没有则分配未被占用的 `NET{n}`。
