# Gerber 导入解析问题根因分析

> 基于源码 + 7 个问题文件实测（`Temp/测试gerber/`）。结论均标注代码位置与证据。

## 共同病灶：`effMode` 推断只有三条规则

`iframe/js/05-pad-tool.js` L335-338：

```js
const effMode = hasSectionMarkers ? mode
    : (cmd.type === 3) ? 'PAD'                                  // ← 不看图层、不分 pad/via
    : (cmd.type === 1 || cmd.type === 2) ? (isCopperLayer ? 'TRACK' : 'POLY')
    : mode;                                                     // ← type4 区域保持 'NONE'
```

无段标记的文件里 `mode` 永远是 `"NONE"`，所以：

| # | 症状 | 直接原因 |
|---|---|---|
| 1 | 过孔↔焊盘错判 | 所有 Flash 一律 `PAD`；过孔焊盘也被当焊盘 |
| 2 | 矩形焊盘"变成过孔" | `consolidate` 的 `tryMergeDrillToPad`：单面焊盘直接 `return` 不合并，于是 pad 与独立 via 叠在同一点 |
| 3 | 丝印文字/logo 丢失 | G36 区域落在 `else` → `rawFills`，`layerId` 原样透传（丝印层 3/4），导出 FILL 到丝印层不被支持 |
| 4 | 覆铜没有专门通路 | `rawCoppers` 是 `consolidate` 的形参，`extractRawData` **从不产出**，恒为空数组 |
| 5 | 走线变粗 10→33.5mil | 区域轮廓的 D01 复用当前光圈。1.4 铜层实测：`0.25mm`(9.84mil) 与 `0.85mm`(**33.46mil**) 都在文件里；区域轮廓真的用 1.1/1.7/1.9/2.3mm 大光圈 |

## 各来源实测

### v2.1 与 v2.2 的实测对比（与预期不符）

两版铜层段落**结构完全一致**：

```
G04 Copper Start*
G36*
G01X166370Y-574040D02*
... (弧/线)
G37*
G04 Copper End*
```

段标记集合也相同：`Copper / PolygonModel / Pad / Via / Track Start·End`。
→ **"v2.1 需要单独解析器"这个前提，在铜层与段标记层面不成立**，需要另行确认差异现象
（可能是内层映射、层数处理，或某个特定层的表达）。

## EasyEDA 标准版 v6.5 的结构差异

- 有 `G36/G37` 区域：stm32 的 TopLayer 有 **462 个**、GTO 有 **112 个**
- 光圈里出现 `O`（椭圆形）与 `MACRO1..MACRO26` 参数化宏
- **无任何 `G04 ...Start/End` 分段** → 覆铜/贴片焊盘/文字全部依赖推断 → 全丢

## 用户备注要求（承载方式）

- **覆铜** → 用折线 API/源码导入**轮廓**，需把多段离散折线**合并闭合**
- **填充区域** → 用填充区域 API/源码导入
- **由填充组成的文字** → 用填充区域导入；文件明确标记为文字时可转图片

## 结论

7 个症状里，**5 个来自同一个推断函数**；真正的"来源方言"差异只有两类确证：
EasyEDA 标准版 v6.5、P-CAD/RS-274D。修推断的投入产出比远高于按文件加解析器。
