# 铺铜填充「相邻块之间约 0.2 mil 缝隙」的根因与修复

测试样本：`Gerber_PCB1_2025-01-11.zip`（内层 1 = 内部层号 15 = 标准版 21 层，一条负片平面：
1 个外环 + **227 个挖空**）。全部数据由 `Temp/scripts/checks/` 下的脚本在真实 Chrome 里跑出来。

---

## 一、结论先说

缝隙有**两个独立来源**，必须同时修：

| 来源 | 环节 | 大小 | 影响范围 |
|---|---|---|---|
| ① keyhole 开缝（把带孔的覆铜拆成无孔小块时，从孔向区域外切的那条缝） | **导入 / 图元生成** | 0.01 mm = **0.39 mil** | 标准版 + 专业版都受影响 |
| ② 覆铜 FILL 的 `width` 字段写了 **0.2** | **导出（仅专业版图元）** | 再叠加 **0.2 mil**（EDA 按线宽把填充整体内缩） | 只有专业版 |

你量到的 0.2 mil 基本就是 ②；而 ① 一直在，只是被 ② 盖住一部分。标准版没有线宽字段，
所以标准版的缝 = ① 的 0.39 mil；专业版 = ① + ② ≈ 0.59 mil。

另外还有一个「被拆成大量细碎小块」的问题：**旧策略是「每个孔各切一条缝通到区域边界」**，
227 个孔就在平面上割出 227 条切口 → 一条内层平面被切成 **688 块**填充（每块之间都是缝）。

---

## 二、为什么会有「开缝」

两套导出格式都只能画**单环**填充：

- 标准版 `SOLIDREGION`：一个 `pathStr`，单条闭合折线；
- 专业版 `FILL`：`path` 里**第一个环是外框，其余环会被当成"又一坨铜"**（实测结论，
  见 05-pad-tool 的注释），不是"挖空"。

所以带孔的覆铜只能拆成「若干个无孔的简单多边形」。把孔变成"开口凹槽"的标准做法就是
开一条从孔到区域外的窄缝（keyhole）—— 缝两侧是两块不同的填充，中间必然是空的。

## 三、改了什么

### 1. 导出端：FILL 线宽 0.2 → 0（`05-pad-tool.js`）

```js
// V3：content.width
"width": 0,          // 原 0.2
// V2：数组第 5 位
["FILL", id, group, net, layer, 0, 0, rings, 0]   // 原 0.2
```

EDA 会按线宽把实心填充往里收，0.2 就是每边 0.1 mil、相邻两块合起来 0.2 mil —— 这就是
你量到的那个 0.2 mil。注意内层焊盘的 FILL（另一处）早就写成 0 了，只有覆铜这一处漏了。

### 2. 导入端：开缝策略从「每孔切到边界」改成「最小生成树 + 一条出口缝」

`06-utils.js fillSplitNegativeRegion()`：

- 孔与孔之间用 **Prim 最小生成树**两两搭缝（O(n²)，227 个孔 ≈ 5 万次距离计算）；
- 整棵树只开 **一条**出口缝到区域外，方向取「离区域边界最近的方向」（旧实现一律水平切到
  最右边，长缝经常横穿整块铜把它劈成两半）；
- 边缘碎屑（面积 < 0.001 mm²）直接丢弃。

效果：一条 227 孔的内层平面 **688 块 → 2 块**（其中 1 块是 0.03 mm² 的真实小岛）。

### 3. 导入端：缝宽 0.01 mm → 0.0002 mm

`FILL_SLIT_HALF` 0.005 → **0.0001**（缝宽 0.0002 mm = **0.008 mil**）。
比制板/DRC 的最小间距（0.075 mm）小两个数量级，画布与 EDA 里都看不出来。

> ⚠️ 记录一个走过的弯路：试过「拆完之后把每块向外膨胀 0.006 mm」来把缝合上。
> **不能用** —— 膨胀会把缝两侧合拢，而缝正是孔洞与外界的唯一通路；一旦合拢，孔洞就变成
> 多边形内部的洞（单环填充表达不了）→ 被当成铜填死。实测层 15 的 227 个孔共 340 mm²
> **全部被填死**。所以只能「留一条极窄的缝」，不能「膨胀合缝」。

## 四、实测数据（同一份样本，改前 vs 改后）

| 指标 | 改前（V3.9.17） | 改后 | 说明 |
|---|---|---|---|
| 内层 1 填充块数 | **688** | **2** | 688 → 1 整片 + 1 个 0.03mm² 小岛 |
| 相邻块最小间隙 | 0.01 mm（0.39 mil） | **0.00022 mm（0.0087 mil）** | 缩小 45 倍 |
| 专业版 FILL 线宽 | 0.2 mil | **0** | 去掉 EDA 侧内缩 |
| 专业版 FILL 条数（全板） | 845 | **487** | −42%，EDA 里少建 358 个图元 |
| 标准版 SOLIDREGION（内层 1） | 688 | **2** | |
| 铜面积（层 15） | 预算 2144.92 mm² | 2144.88 mm²（−0.002%） | 只剩缝本身占的一点点 |
| 挖空（孔）保留 | 227 个 340 mm² | **全部保留** | 面积对账 −0.03 mm² |

其它样本（都只有正向区域、没有挖空）不受影响：`06-10` 1 块、`10-16` 6 块、`05-21` 3 块。

## 五、验证方式（脚本化，可回归）

都在 `Temp/scripts/checks/`，用本机 Chrome 跑真实前端：

1. **`fill_gap_probe2.js <zip>`** — 打印：原始填充的挖空数、拆分后块数 / 相邻块最小间隙、
   专业版 FILL 条数与 `width`、标准版各层 SOLIDREGION 条数。改后应为
   `pieces: 2`、`minGap: 0.00022`、`width: 0`。
2. **`fill_seam_check.js <zip> <layer>`** — 面积对账：`预算 = 外环面积 − 挖空面积`，
   与「各块面积之和」比较。`delta ≈ 0`（允许 −0.01%）说明①孔没被填死 ②缝没漏铜。
   改后 `delta = −0.032 mm²（−0.002%）`。
3. **`fill_render_shot.js`** — 把拆分结果渲染成 PNG（24 px/mm），肉眼看孔洞与缝隙；
   改后 `Temp/shots/fill_split_layer15.png` 是一整片铜、孔洞齐全、只有几条发丝般的树状缝。
4. **`fill_drop_check.js <zip>`** — 确认 `uni.fills` 与最终 FILL 条数对得上（不能被丢块）：
   改后 `fills 481 / fillPrims 487 / dropped 0`。
5. **`fill_ring_check.js <绝对路径>`** — 严格 mock 校验每个环（零长边 / 未闭合 / 点数过少）：
   改前改后都是 `zeroSeg 0 / unclosed 55 / tooFewPts 107`（55/107 是历史上就有的小焊盘环，
   与本次改动无关，条数一致 = 没有引入新问题）。
6. **`net_health.js <zip>`** — 网络健康度：改前改后都是 207 个网络、
   `mixedClusters 0`、`sameNameMultiIsland 2` —— 拆分策略变化没有影响网络判定。

## 六、回归测试要点（以后动这块时逐条过）

1. **带 227 孔的内层平面**（`Gerber_PCB1_2025-01-11.zip` 层 15）：块数 ≤ 2、`minGap < 0.001 mm`、
   面积 delta 在 −0.05% 以内；
2. **孔不能被填死**：`fill_seam_check` 的 delta 若变成 +15%（正数且接近挖空面积），
   就是走了「膨胀合缝」的老路；
3. **无孔的正向区域**（06-10 / 10-16 / 05-21）不能因为新逻辑被多切一刀；
4. **两套导出都要看**：专业版看 `FILL` 的 `width === 0` 与条数；标准版看 SOLIDREGION 条数与层号映射
   （内层 1 → 标准版 21，2 → 22…）；
5. **网络与飞针**：`net_health` 的 `mixedClusters` 不能增加；飞针焊盘编号不受影响；
6. **大板性能**：21MB 样本导入不能明显变慢（本次 2305 ms，改动前 2347 ms，反而略快，
   因为 EDA 侧要建的填充图元少了一半）。

## 七、仍然存在的限制

- 单环填充**天生不能带孔**，所以「缝」不可能彻底为 0；当前 0.0002 mm 已是「不可见 + 远小于
  任何 DRC 阈值」的水平。要做到严格 0，只能换图元（例如标准版的 COPPERAREA / 专业版的
  铺铜压缩数据），或者把缝两侧的顶点吸附成**零宽的桥接边**（重合边）—— 后者理论上可行，
  但依赖 EDA 对退化多边形的处理，不建议在没有实机验证的情况下启用。
- 若某块覆铜被挖空到只剩极细的铜桥，树状缝可能把它切断成 2 块（当前样本只剩 1 个
  0.03 mm² 的小岛）。这种情况属于几何本身的连通性，不是缝隙问题。
