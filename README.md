# Gerber 转 PCB（嘉立创 EDA 专业版扩展）

查看 Gerber 制造文件，并将其转换为 **嘉立创 EDA 专业版 / 标准版** 的 PCB 文件，或直接导入当前 PCB 画布。  
工具**完全离线运行**：文件解析、渲染、导出全部在本地完成，不联网、不上传任何服务器。

> [演示视频](https://pbt-pub.jlc.com/pbt/bbs/8707762781426302976-20260205_220643.mp4)

## 一、使用前必读（重要）

> **本工具会直接读写 EDA 编辑器画布。请务必新建一个空白 PCB 文档后再使用导入功能。**  
> **严禁在包含现有设计数据的 PCB 文档中执行导入。** 因未在空白文档操作、未提前备份或操作不当  
> 造成的数据丢失、文件损坏或不可逆修改，**均由用户自行承担，开发者概不负责**。

- 大量图元（数万个）**通过图元导入**时可能造成 EDA 卡顿，建议改用「导出 PCB 文件」后再导入。
- 生成的工程文件**仅供参考，严禁未经人工复核直接用于 PCB 生产制造**。
- 本工具为开源辅助软件，**按「现状」提供**，不保证准确性、完整性或特定用途适用性。

## 二、使用方法

1. 在嘉立创 EDA 专业版中，通过 PCB 顶部菜单 **「Gerber工具 → 导入Gerber」** 打开本工具；  
   同菜单下的 **「Gerber工具 → 关于」** 可查看开发者信息、使用方法与免责声明。
2. 导入文件，三种方式任选：
    - **导入当前板子 Gerber 图形**：工具调用 EDA API 直接获取当前 PCB 的 Gerber 数据；
    - **导入 Gerber 压缩包 / 文件**：弹出文件选择窗口，选择 `.zip` 压缩包或多个 Gerber 文件；
    - **直接拖拽**文件到工具窗口。
3. **配置**：在右侧面板调整处理模式、单位/坐标精度、图层映射与各图层显示。
4. **导出**：切换到「导出选项」标签页，选择需要的导出方式（见下）。  
   其中 **「通过源码导入 / 通过图元导入」写的是当前打开的 PCB 文档**：工具打开时会读取 PCB 源码做检测，  
   若本工具是从开始页 / 原理图 / 符号库等非 PCB 页签打开的（读不到 PCB 源码），这两个入口会被**禁用**并给出提示 ——  
   请先打开或新建一个 PCB 文档，再重新打开本工具。

### 导出方式对比

| 导出方式                 | 说明                                                               |         埋盲孔         |    可撤销    |
| ------------------------ | ------------------------------------------------------------------ | :--------------------: | :----------: |
| **通过源码导入**（推荐） | 生成源码写入当前 PCB，最完整                                       |          支持          |    可撤销    |
| **通过图元导入**         | 逐个调用 API 创建图元                                              | 需先手动添加埋盲孔规则 | 无法完全撤回 |
| **导出嘉立创 EDA**       | 生成 `.epro2`（V3）/ `.epcb`（V2）专业版工程文件，或标准版 `.json` |       视版本而定       |   本地文件   |
| **导出位图 PDF**         | 按键/分层输出，DPI 可自定义（越高越清晰）                          |           —            |   本地文件   |

## 三、处理模式

「处理模式」下拉决定**怎么解析输入 Gerber、怎么判断每个文件属于哪一层**；输出统一走嘉立创的导出流程。

| 下拉项                | 状态 | 说明                                                                          |
| --------------------- | :--: | ----------------------------------------------------------------------------- |
| **嘉立创 EDA 专业版** | 支持 | 读取嘉立创专业版私有段标记（`G04 Pad Start` 等），还原最完整、最准确          |
| **RS-274X（通用）**   | 支持 | 通用 RS-274X；无私有段标记时按「图层 + 指令类型」推断图元，图层按通用命名识别 |

- **自动识别**：导入后按内容特征（`%TF`/`%ADD`/`G70`/`G54D` 等）与文件名约定打分，自动切换到匹配的模式并写入运行日志；无法判定时保持当前选择。
- 两个模式之外（如 Gerber X2/X3 的 `%TF`/`%TO` 属性、RS-274D 的外部孔径表、`%SR` 步进重复）**暂未提供专用解析器**，会用 RS-274X 尽力解析，属性信息不消费。

### 4.3 明确不支持 / 限制项

- **真彩图片**：**不支持，且离线无解**。彩色丝印/图案不是以 Gerber 形式给出的，而是单独打包在 `Fabrication_ColorfulTopSilkscreen.FCTS`、`...BottomSilkscreen.FCBS`、`...BoardOutlineLayer.FCBO` 里 —— 这三个文件**不是 RS-274X**，而是加密容器：
  - 容器结构固定为 `256 B RSA-OAEP(SHA-256) 密文（封装 AES-128 key）` + `256 B RSA-OAEP 密文（封装 GCM nonce）` + `N B AES-128-GCM 密文（明文是一份 SVG）` + `16 B GCM TAG`；
  - 实测特征：香农熵 7.997 bit/byte、256/256 种字节、无任何明文头、无压缩流魔数 —— 从第 0 字节起就是密文；
  - **AES 密钥由嘉立创公钥 RSA 封装，私钥只在其服务端**，因此离线不存任何可解路径（第三方逆向资料结论一致）；
  - 同一批导出的普通 Gerber 里也确实没有它：信号层往往是**空的**，`GKO` 只有板框矩形，`FCBM` 只有板框 + 3 个 Mark 点 —— 图只存在于上述加密容器中。
  
  工具会按未知文件跳过这些 `.FCTS/.FCBS/.FCBO`，不影响其它层的导入；如需彩色丝印效果图，只能在嘉立创EDA里打开原始工程预览导出。完整分析见 `Temp/FCTS_解析报告.md`（含结构验证与解密工具，但那需要导出时钩到的 key/nonce）。
- **FPC 补强**：支持，但**只能通过「通过源码导入」写入**。识别 `Gerber_<Top|Bottom>StiffenerLayer_<材料码>_<厚度>.GTSL/.GBSL`，解析文件名里的材料与厚度，生成 `FPC_FILL` 图元（layer 58 / 59），并自动把板类型切为 FPC。
  - 材料码按实测样本映射：顶层 `pit/fr4t/gpt/csa`、底层 `pib/fr4b/gpb/ssa`、`pst_<型号>`/`psb_<型号>` 取型号为材料名；
  - **未知材料码不猜**：补强形状仍会导入，但退化为普通填充（材料/厚度不写），运行日志会给出数量；
  - **任意形状补强**都写成 `FPC_FILL`：轴对齐矩形用最简的 `R` 快捷式 `[["R",x,y,w,h,0,0]]`，其余形状（L 形、多段折线、圆角矩形等）用通用路径式 `[[x,y,"L",…,"ARC",扫角,x,y,…]]`，与 EDA 官方导出的多边形补强源码同构。
  - **「通过图元导入」不支持补强**：实测 `pcb_PrimitiveFill.create()` 无法把图元写到补强层 58/59 —— 即使先 `setPcbType(FPC)` 让补强层存在，接口仍返回空或把图元落到默认层（表现就是「补强变成顶层一块填充」）。因此该通道会**跳过补强**并在运行日志/吐司提示改用源码导入，也不会再切换板材类型。
- **标准版导出**：不输出 `STRING` 文本图元、埋盲孔；**元件位号会以 `TEXT` 图元输出**（自带字形轮廓，见 4.4）。Gerber 里由笔画组成的丝印文字仍作为折线（`TRACK`）还原，不是可编辑文本。
- **光圈宏**：仅支持基元 1/4/5/20/21/22；Moiré（6）、Thermal（7）未绘制，含复杂表达式的宏为尽力而为。
- **`%SR` 步进重复**、**Gerber X2/X3 的 `%TF`/`%TO` 属性**：未处理（几何可解析，属性被忽略）。
- **`PCB / FPC` 文档类型开关**：手动切换不影响解析与导出结果；导入含补强层（58/59）的 Gerber 时会自动切到 FPC。
- **钻孔图层（GDD）默认不显示、不导出**，需在图层设置中手动勾选。
- **专业版 V4**：「通过源码导入」已支持（读取 `getEditorCurrentVersion()` 的 `4.*.*`，按 V4 文档头写源码）；**不导出** V4 工程文件（`.epro2`）。
- **仅适配嘉立创 EDA V2.2 及以上版本导出的 Gerber**；其它软件（KiCad / Altium / PADS / P-CAD / Eagle / layout60 等）的 Gerber 可尝试用「RS-274X（通用）」解析，但兼容性不作保证。
- 板子较大 / 图元较多时界面会卡顿；建议分图层处理或改用文件导出。
- 写画布前会校验当前文档是否为空并弹出覆盖警告；但该保护为「尽力而为」，**无法替代用户自行备份**。

### 4.4 特殊功能

- **埋盲孔**：可手动指定钻孔文件的起始层与结束层（如「内层1」到「内层2」），生成对应层对规则。
- **阻焊 / 助焊扩展**：自动计算焊盘的阻焊与钢网扩展量（含宏光圈焊盘）。
- **坐标精度**：可手动调整整数位与小数位，解决 Gerber 导入比例错误。
- **飞针标注**：导入的压缩包若含 `FlyingProbeTesting.json`，可在画布叠加显示**引脚编号**、**网络名称**与**元件位号**（前两者仅显示，「元件位号」勾选后写入**文档层**文字，字高 30 mil）。
- **FPC 补强（Stiffener）**：自动识别 `*StiffenerLayer_*` 文件并归入补强层（58 / 59），从文件名解析材料（Polyimide / FR4 / Stainless Steel / TESA8854 / EMI Shielding Film）与厚度，生成带材料属性的 `FPC_FILL` 图元，同时把板类型切为 FPC。**该能力仅「通过源码导入」支持**（图元 API 建不出补强，见 4.3）。画布上会在每块补强中心标注「材料简称 + 厚度」（PI / FR4 / 钢片 / 双面胶 / 电磁屏蔽膜，颜色 `#193366`），该标注可在图层面板的「补强名称」行单独关闭。
- **专业版 V4 写入**：在 4.x 客户端里使用「通过源码导入」时，自动按 V4 文档头（含 `LAYER_PHYS`、`D3_ATTRIBUTE` 与新增显示配置）生成源码；图元行与 V3 完全一致。仅支持写入当前画布，不产出 V4 工程文件。
- **标准版折线 → 导线**：标准版没有折线（`POLY`）图元，所以导出时**所有折线一律转成带线宽的多点 `TRACK`**（一条折线 = 一条多段 TRACK，不拆散），并允许落在非铜层（丝印 / 文档 / 机械 / 装配）。实心区域仍由 `SOLIDREGION` 承载，两者互不影响。
- **标准版文字（内置字体轮廓）**：元件位号在标准版里输出为 `TEXT` 图元，格式与官方一致：
  `TEXT~L~x~y~0.8~0~0~12~~<em>~文本~M…Z~~ggeID~NotoSansCJKsc-DemiLight~0~pinpart`。
  因为浏览器 / EDA iframe 拿不到字体的矢量路径（canvas 只能画、不能导出 path），所以项目**内置了一份字体轮廓** `iframe/js/11-font-outline.js`（Noto Sans CJK SC DemiLight，默认提取 ASCII 0x20–0x7E，94 个字形）。
  - 位号字高 **30 mil**（指字符实高 cap height，运行时按字体的 cap/em 比反算 em）；统一写到**文档层**。
  - 重新生成 / 扩充字符集用 `tools/font-outline.js`：
    ```bash
    npm i opentype.js --prefix Temp/fonttest --no-save
    NODE_PATH=Temp/fonttest/node_modules node tools/font-outline.js --extra "从电源地"
    NODE_PATH=Temp/fonttest/node_modules node tools/font-outline.js --range 0x4E00-0x9FA5
    ```
    工具会从 TTF/OTF 提取字形轮廓（每条子路径显式闭合），写出数据 + 运行时拼路径函数；缺字会在运行日志里列出。
- **网络名冲突改名**：生成网络时，如果两个**各带不同已知网络名**（来自飞针 `NET_NAME`）的分量被几何判定连在一起，以前是拒绝合并、现在**允许合并并整块改名**为一个未被占用的 `NET*`（如 `NET1`、`NET2`，跳过已占用的名字）。两个原网络名都从结果里消失 —— 既不会出现「同一网络落在两个互不相连的分量上」的飞线，也不会静默沿用其中一个可能是错的名字。运行日志会给出改名分量数。

## 五、适用场景与限制

**适用场景**

- 个人学习、电路设计研究与教学演示；
- 对已停产、无原厂支持设备的维修与兼容性分析；

- 逆向还原依赖几何推断，无法百分之百还原原始设计（网络、元件属性、真彩图等）；
- 跨软件 Gerber 的图层命名差异可能导致归层不准，需人工核对图层映射；
- 转换结果可能出现图形丢失、孔径误判、层属性识别偏差等误差；
- 非生产级工具，**不得**作为生产制造的唯一依据。

## 八、项目结构

界面与业务逻辑已按职责拆分为多个独立文件（原为单个约 315 KB 的 `iframe/ImportGerber.html`），便于维护与定位问题。

```
iframe/
├── ImportGerber.html        主界面骨架：结构 + 样式/脚本引用
├── About.html               「关于」页面：开发者 / 使用方法 / 免责声明
├── css/
│   └── style.css            全部界面样式
└── js/
    ├── jszip.min.js         第三方库（ZIP 打包）
    ├── jspdf.umd.min.js     第三方库（PDF 生成）
    ├── clipper.js           Clipper 6.4.2（多边形布尔运算，负片转正片用）
    ├── about.js             「关于」页面脚本（读取 extension.json 填版本号）
    ├── 01-templates.js      工程文件头模板常量（STD / V2 / V3）
    ├── 02-config.js         调试开关、全局变量、图层定义与文件名识别规则
    ├── 03-state.js          运行时状态、画布上下文、免责声明弹窗、PCB 画布门控
    ├── 04-gerber-parser.js  Gerber 解析器（按处理模式启用特性）
    ├── 05-pad-tool.js       逆向还原引擎（提取 / 聚合 / 生成图元）
    ├── 06-utils.js          通用工具函数（含 PCB 画布检测、网络生成引擎）
    ├── 07-file-io.js        文件导入与解析调度（含自动识别处理模式）
    ├── 08-export.js         导出控制器（画布注入 / 工程文件 / 标准版 / PDF）
    ├── 09-ui.js             UI 渲染与交互
    ├── 10-init.js           初始化与全局事件
    └── processors/          处理模式模块：一个模式一个文件，由注册表路由
        ├── registry.js          注册表 + 路由 + 自动识别引擎
        ├── industry-common.js   行业公用（图层识别规则 / FileFunction 解析）
        ├── industry-rs274x.js   RS-274X（通用）
        └── jlc-internal.js      嘉立创 EDA 专业版内部标准
```

**脚本加载顺序不可调整**：文件名数字前缀即加载顺序，脚本以经典 `<script>` 方式共享同一全局作用域，  
后置模块依赖前置模块的全局定义；`ImportGerber.html` 中的标签顺序与上表一致。

- 修改功能时请按职责定位到对应文件，不要重新把脚本内联回 HTML。
- `01-templates.js` 是「由 EDA 导出的模板文本」，请勿手工格式化或调整缩进。
- `.js` / `.css` 均带 UTF-8 BOM，可在服务端未声明 charset 时仍正确解析中文。
- 改动后建议执行语法自检：`node --check iframe/js/*.js`

## 九、构建

```bash
npm install
npm run build   # 产出 build/dist/eext-gerber-import_v<version>.eext
```

版本号以 `extension.json` 为准，`package.json` 同步维护。构建时按 `.edaignore` 过滤，  
仅打包运行期必需文件（`dist/`、`iframe/`、`extension.json`、`locales/`、`images/logo.png` 等）。
